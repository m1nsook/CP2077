# Kineticle 0.1.0-dev.13-native-chassis-mass

Replaces dev.12's obsolete signatures with the exact 2.50 native chassis mass refresh route verified offline from the supplied executable (PE timestamp 0x6AD55DAF) and address map. No game executable or extracted executable file is included.

Static analysis: vanilla toggle at RVA 0x81e17c (hash 1585713002) inlines the alternative float and presence flag at RigidBody +0x1b4/+0x1b8; true path loads 100000.0 kg, false clears the flag; both call refresh at 0x81e110 (hash 4183691991). Refresh locks the chassis handle at vehicle+0x2f0 and calls update at 0x81d718 (hash 841094152). The update selects +0x1b4 if present, otherwise +0x1c0, and submits the chosen mass through the native physics proxy writer at 0x81d89c (hash 2719813719). This path does not rewrite the integrator total mass or inverse mass. Existing loader/executable checks, exact timestamp, resolver/RVA agreement and opcode validation are mandatory. No old pattern fallback.

The experiment sets only the two instance optional-mass fields and invokes the verified refresh routine. A scoped observer confirms the actual mass command and actor index before counting an apply/restore. This proves command submission, not PhysX consumption or gameplay behavior. No shared TweakDB edits, NPC writes, velocity correction or per-bump RTTI. Restoration restores the original optional value/flag and refreshes the vanilla chassis mass; an unavailable or replaced old body blocks new application until restart. Exact selected entity, current physics body/chassis identity, fresh controller validation, dynamic state and player flag are required. On stale scope, exit, disable or vehicle change, restoration is attempted at next matching physics update. Native refresh thread-context and final PhysX effects remain unverified in game. The modifier may change collisions with walls/objects as well as vehicles. This development mass experiment still requires M1 Arc; Core protection remains independent.

The controller now records rejected settings once per requested value instead of repeating the error each tick. Native requested value is read back. If M1 Arc refuses to update its slider, the native value remains authoritative. No hot unload with active mass.
