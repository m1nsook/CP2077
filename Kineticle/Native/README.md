# Kineticle 0.1.0-dev.15-scope-recovery

Standalone Core requires only RED4ext 1.31.1 and game executable 3.0.88.46235. The optional M1 Arc controller reads/writes the native configuration, reports diagnostics, and temporarily supplies the proven dev.13 driver scope bridge. Native-only authorization is separate and remains unverified. Do not install old REDscript Core packages alongside the native DLL.

## Installation and settings
Install Core plus exactly one controller: M1 Arc, NSUI (CET + NSUI 1.97 + REDscript), or Mod Settings (REDscript + Mod Settings 0.2.35). No JSON edits required. Uninstall the previous controller before switching, because controllers share native declarations and driver authorization. Internal config.json is persisted by Core. The two alternate controllers ship the identical proven dev.15 driver bridge; M1 Arc keeps its existing bridge. The NSUI tab uses Core getters/setters and debounces mass updates. Mod Settings stages any mirror differences on opening its screen and uses only its own accepted variable callbacks; user Apply is required. It never accepts another mod's changes. No diagnostic buttons.

## Native mechanism
Preserves dev.13's executable timestamp, resolved addresses, byte checks, optional mass fields, native refresh and command observer. No NPC mass writes, shared TweakDB changes, integration hook, or synthetic velocity writes. The RED4ext Running callback samples local player and exact mounted vehicle on the game update thread every 100 ms, using driver, mounted, road type, remote, quest, destroyed, locked, PSM and tag checks. Physics sync only uses fresh authorization (250 ms), exact entity/body/chassis identity, player flag and dynamic state. Restore original alternative value and normal chassis mass on matching body sync after dismount/disable/transition. If a prior modified body disappears before restoration, new modification is blocked until restart. A failed native command or external change latches mass unavailable until restart, preserving saved requested configuration. No hot unload. Collision response against environmental objects may change; no claim of vehicle-only contact filtering.

## Verification
dev.13 user-confirmed native mass: 15 applies, 15 restores, 30 commands, no command/readback/restore failures. dev.14 regressed in-game at 25x. dev.15 restores dev.13 controller authorization, keeps native-only scope separate, and preserves persistent settings. The exact dev.14 failure is not proven without its diagnostic report. Native mechanical callback unverified; grid/glass existing implementation optional, off by default. Tire/occupant protection remains deferred. NSUI and Mod Settings adapters are development packages and require runtime testing. Old impulse and contact tracing code excluded from runtime and active tests.

## Test

The controller automatically logs startup diagnostics, and Core saves its native diagnostics to disk. Diagnostic buttons are intentionally not exposed. CORE_SCOPE and CONTROLLER_SCOPE are separate; MASS must show a positive apply count, effective last_applied_mass, and matching restoration. Standalone mode remains experimental until independently validated. Do not merge/release before runtime confirmation.

The M1 Arc settings page exposes gameplay controls only. Native diagnostic APIs and automatic startup logs remain available for support.
