# Kineticle native motion development build (dev.9)

Standalone Core requires RED4ext only. Optional M1 Arc controller supplies settings, report actions and sampled player context. Install both matching archives for the comprehensive test. Do not mix with the dev.5 REDscript fallback or old native controllers. Version-gated to game executable 3.0.88.46235 / RED4ext 1.31.1.0.

**Experimental gameplay writes are off by default.** The consolidated diagnostics remain active. It measures the existing verified sync and bump dispatcher hooks, checks all available safe guards independently on both vehicles, captures per-query failure reasons, physics-state masks, masses, inverse mass, timing, velocities, angular velocities, force/torque accumulators, and dry-run recovery/impulse estimates. Nearby duplicate events are flagged rather than discarded. The estimates use observed sync delta velocity, not a proven contact impulse. The address checks for native impulse functions do not call them. The 8-event histories and 512-sample ring are bounded; the post-sync timing excludes the original physics function, pre-sync work and some early returns. No exact process-memory or allocation profiling is claimed.

The optional controller samples player presence, mounted vehicle identity, driver, PSM vehicle state and all three known restriction tags every 0.5 s while diagnostics are enabled, and every 0.1 s during the experimental motion session. Each pair reports the sampled context, its age and whether the ID/time match. This is not exact event-time proof and not standalone native PSM access. PSM values: -1 unknown, 0 default, 1 driving, 2 combat, 3 passenger, 4 transition, 5 turret, 6 driver combat, 7 scene.

Report writes the complete snapshot to `red4ext/plugins/Kineticle/diagnostics.txt` using atomic replacement, with numbered bounded M1 Arc log pages as a secondary transport. A normal unload also writes a report when no manual capture succeeded; a crash may prevent that fallback. Reset resets counters/history; it does not erase the existing disk report. Report again before sending the file. Old logs are retained by M1 Arc; prefer the disk file. No full WolvenKit export needed.

## Paired-motion experiment

Dev.7 identified 26/26 player collision pairs, 23 passing native guards; the three candidate-flag disagreements must remain rejected. Real car and bike traces showed almost equal and opposite momentum changes on separate worker threads. The test uses the [same post-sync rigid-body velocity adjustment point demonstrated by LTBF](https://github.com/jackhumbert/let_there_be_flight/blob/main/src/red4ext/Physics/ChassisContacts.cpp), not an unverified impulse ABI.

Explicitly enable **Experimental paired motion (session only)** in the optional M1 Arc controller. The setting starts off on every attach and is not stored by Core. This initial safety-gated test requires that controller's fresh typed player-state sample; standalone Core still runs diagnostics but cannot arm experimental writes without that context. This is an acknowledged development limitation, not the final standalone gameplay architecture.

- Exactly one native player driver, both road vehicles, neither destroyed/remote/quest controlled, candidate flags consistent. Event-state traffic may transition to dynamic; the driver sample and all actual writes require mask zero; an NPC Traffic (1) sample is allowed for observation only.
- Up to eight meaningful post-event corrections per vehicle within 65 ms; selected corrections must occur within 5 ms of each other with matching simulation delta, valid mass/inverse mass, opposite momenta within 12%, and V approaching the target with forward loss. Reject ambiguous overlapping events and samples not satisfying the checks.
- At the matched dynamic target sync if it completes the pair, or at a later clean dynamic target sync, add one extra horizontal copy of the observed target delta (nominal 2x; cap +8 m/s). At a later clean sync of V, only with a post-event player context confirmation, recover 50% of the observed horizontal forward loss (cap +4 m/s). Both writes use only that callback's own body and preserve vertical speed; no waiting between physics workers or cross-body pointer writes. No angular, mass, handling, damage, tire, injury or wall-specific changes. Reject a new meaningful correction, stale context, physics-state change, candidate/mass change, excessive velocity drift, final speed >85 m/s, or a transaction older than 220 ms.
- The two writes are not atomic: target may receive the experimental correction and V recovery may subsequently be rejected. Such cases are counted as partial. No exact physics contact ID or guarantee about simultaneous environmental contact is claimed. This is opt-in experimental code, not a production-safe wall-exclusion proof.

Dev.8 armed 21 attempts and accepted zero. The real bike/traffic pair had a 6.74% full momentum residual and NPC state 1. The new sampler permits this measurement without enabling writes to traffic or kinematic bodies. The matcher retains multiple candidates and rejects the transaction only after the correlation window ends if no valid pair is found. A post-event player sample is required for V recovery, protecting against the driver loss observed in the test. Traffic state is never forced to change. A full attempt history (up to 32 armed attempts) includes both chosen sample states, timings, residual, candidate counts and delivery outcome.

The file reports MOTION_TRIAL armed/plans/NPC_writes/V_writes/completed/partial, rejection counts, and the last 16 actual before/after velocity assignments. A write is not proof that downstream simulation preserved it; the user must verify the game response. Offline tests replay actual dev.7 car and dev.8 bike/traffic samples and cover timing, momentum, false flags, dynamic state, target-first delivery, duplicate prevention, new corrections, context, expiration, and partial writes.

## One test session
1. Reset while on foot. Walk/stand, enter car, drive normally, hit a wall, collide with another vehicle (including head-on), then exit. If practical, repeat with a bike and try passenger or remote control. Do not seek quest states that are unavailable.
2. Enable the experimental switch after a baseline drive. Hit several moving/dynamic cars and a wall separately; try a bike if practical. Disable the switch and repeat a normal collision. Press Report once after the final test. Send diagnostics.txt; if it fails, copy numbered M1 Arc diagnostics.
3. With the experiment off, no gameplay difference is expected. Guard results of -1 are unknown, not false; temporal matches are not causal proof.

## Remaining work
Exact contact identification at the physics layer, experimental velocity delivery in game, standalone event-time PSM/status tags, simultaneous environment contacts, angular correction, and native damage/visual/tire/injury hooks remain unverified. Unsupported or unknown checks must never be treated as permission to modify gameplay. No new guessed offsets or third-party runtime dependencies.
